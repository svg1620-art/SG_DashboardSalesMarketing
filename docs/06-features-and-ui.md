# 06 — Функции и интерфейс

## Роли и доступ

Роли по возрастанию прав: `viewer (0) < marketer (1) < admin (2)`.
Декораторы в `app/auth.py`: `@login_required`, `@role_required("marketer")`.

| Роль | Права |
|------|-------|
| **admin** | Всё + управление пользователями + запуск синхронизации |
| **marketer** | Просмотр дашбордов, ввод «Затраты и касания», «Обновить сейчас», экспорт |
| **viewer** | Только просмотр и экспорт |

Пароли — PBKDF2-HMAC-SHA256 (соль на пользователя, 200k итераций). Регистрация
закрыта: пользователей заводит admin в `/admin/users` (создание, смена
роли/пароля, активация, удаление; есть защита от самоблокировки — свою учётку
нельзя понизить/отключить/удалить).

## Панель фильтров

Единая (`templates/dashboard/_filters.html`): период (с/по), менеджер, источник,
**тип клиента**, воронка (пока одна — «Воронка1»). Фильтры применяются к вкладке
и переносятся по ссылкам между вкладками и в экспорт.

При открытии подставляется период по умолчанию (редиректом с датами в URL, чтобы
их несли ссылки и экспорт): дашборды — **текущий месяц**, «По месяцам» —
**текущий год**.

## Вкладки

| Вкладка | Маршрут | Содержимое |
|---------|---------|------------|
| **По источникам** | `/dashboard/sources` | Таблица метрик по источникам + «Все источники»; воронка Chart.js с разбивкой по типу клиента (с этапа SQL, % внутри сегментов). Пустые источники скрыты. |
| **По месяцам** | `/dashboard/months` | Транспонированная матрица (месяцы — колонки, метрики — строки) с подсветкой динамики конверсий; карточки по типам клиента с дельтами; диаграммы: MQL→SQL/SQL→успех и конверсия по типам клиента по месяцам; сравнение месяцев («месяц года» / multiselect). |
| **По менеджерам** | `/dashboard/managers` | Карточки по типам клиента (конверсия MQL→успех + длина сделки) и сводная таблица. |
| **Затраты и касания** | `/dashboard/costs` | Ввод рекламы по источникам и месячных затрат (marketer+). |
| **Сделки** | `/dashboard/deals` | Плоская таблица с поиском (ID/источник/тип) и пагинацией. |
| **Экспорт** | `/dashboard/export` | Выгрузка в Excel. |

Основной модуль расчётов — `metrics.py`. Числовые Jinja-фильтры (в `__init__.py`):
`num`, `money`, `pct`, `ratio`, `dur`, `ctshort`.

## Ввод затрат

Вкладка **«Затраты и касания»** (ввод — marketer/admin, viewer только просмотр):
- **Реклама по источникам** → `costs_touches` (месяц × источник × сумма ×
  касания × комментарий). Upsert по (месяц, источник).
- **Затраты по месяцам** → `monthly_costs` (Расходы на маркетинг, Расходы на
  продажи). Upsert по месяцу.

Правки поверх посеянных миграцией исторических данных сохраняются.

## Экспорт в Excel

`app/export.py` (openpyxl, генерация в память — ФС эфемерна). Кнопка «⬇ Excel» в
панели фильтров каждого дашборда (выгружает текущий вид с учётом фильтров) +
вкладка «Экспорт». Листы: По источникам, По месяцам, По менеджерам, Сделки,
Реклама (затраты), Затраты по месяцам. Значения без формул, с форматами
(проценты `0.0%`, суммы `#,##0 ₽`).

## Нейросеть (анализ по запросу)

`app/ai.py` — кнопка **«🤖 Рекомендации от нейросети»** на страницах «По
источникам / месяцам / менеджерам». **Только по нажатию**, не автоматически.

По клику собираются агрегированные метрики разреза (с учётом фильтров) и
передаются модели `claude-opus-4-8` (официальный SDK `anthropic`, adaptive
thinking). Ответ — разделы «Закономерности», «Аномалии», «Рекомендации»
(безопасный Markdown→HTML рендер). Эндпоинт `POST /ai/recommendations?page=...`.
Без `ANTHROPIC_API_KEY` — понятная ошибка. Каждый вызов — платный запрос к Claude
API (данные компактные, стоит копейки). Системный промпт и сбор данных — в `ai.py`.

# CHANGELOG — история разработки

Хронология по стадиям плана ТЗ и последующим доработкам. Технические детали — в
тематических файлах `docs/`.

## Стадии плана ТЗ

**Stage 1 — Каркас + БД + авторизация** (ТЗ §11)
- Flask-скелет (app factory, блюпринты, gunicorn/`wsgi.py`).
- Модель данных PostgreSQL — все таблицы ТЗ §8, миграции в `migrations/`.
- Идемпотентный раннер миграций + bootstrap администратора (`scripts/migrate.py`).
- Аутентификация email + пароль (PBKDF2), сессии, роли admin/marketer/viewer.
- Проверка amoCRM (`/admin/amocrm-check`): `/account`, воронки, глубина истории.
- Фирменный стиль SG.

**Stage 2 — Движок синхронизации** (ТЗ §6)
- Клиент amoCRM с пагинацией, ретраями, обработкой лимитов.
- Сопоставление статус→этап (посев `migrations/002`), редактируется admin.
- Вычисление этапов (`stages.py`): порядковая воронка, фолбэк, исключение «Дубль».
- Идемпотентный upsert; фоновый синк + журнал; ежедневный автосинк (APScheduler).

**Stage 3 — Дашборд «По источникам»** (ТЗ §4)
- Панель фильтров; метрики по источникам + «Все источники»; воронка Chart.js.

**Stage 4 — Дашборд «По месяцам» + ввод затрат** (ТЗ §4)
- Помесячная когортная воронка; юнит-экономика; вкладка «Затраты и касания».

**Stage 5 — Дашборд «По менеджерам»** (ТЗ §4)
- Метрики по менеджерам (без cost-метрик — привязаны к источнику).

**Stage 6 — Затраты** (в составе Stage 4/5)
- Ввод рекламы по источникам и месячных затрат.

**Stage 7 — Экспорт в Excel** (ТЗ §7)
- `export.py` (openpyxl, в память), 6 листов, учёт фильтров.

**Stage 8 — Вкладка «Сделки» + полировка** (ТЗ §4, §11)
- Плоская таблица с поиском и пагинацией; логи синка; фолбэки и граничные случаи.

**Управление пользователями** (ТЗ §5) — `/admin/users`, защита от самоблокировки.

## Доработки после базовых стадий (по уточнениям заказчика)

- Юнит-экономика приведена к методике исходного листа: CAC = (расходы на
  маркетинг + расходы на продажи) ÷ продажи, прямые месячные тоталы
  (`monthly_costs`); LTV = ARPPU × 21. Сверено — цифры сходятся.
- Посев исторических затрат из таблицы заказчика (миграции 005/006).
- «По месяцам»: транспонированная матрица, подсветка динамики конверсий,
  сравнение месяцев, длина сделки, карточки по типам клиента с дельтами,
  диаграмма конверсии по типам клиента.
- «По источникам»: объединённая воронка со стеком по типу клиента, короткие
  коды МКК/КК/СКК, скрытие пустых источников, «—» вместо «0 ₽» без затрат.
- «По менеджерам»: карточки по типам клиента (конверсия + длина сделки).
- Дефолтный период при открытии (текущий месяц / текущий год).
- Фильтр по типу клиента во всех дашбордах.
- **Нейросеть**: кнопка «Рекомендации от нейросети» (Claude API) на трёх
  дашбордах, анализ по запросу.
- **Сверка синка**: удаление сделок, исчезнувших из воронки amoCRM
  (удалённые/перенесённые), с защитой от массового удаления.
- Документация для разработчиков (папка `docs/`).

# DashboardSales&Marketing — передача проекта (для менеджера)

Документ для менеджера, принимающего продукт в работу. Описывает, **что это**,
**как пользоваться** и **как читать цифры**. Техническая документация для
разработчиков — отдельно, в папке `docs/` репозитория.

---

## 1. Что это и зачем

Внутренняя веб-платформа аналитики воронки продаж и маркетинга. Заменяет старую
Google-таблицу с ручными формулами и нестабильной интеграцией к amoCRM.

**Что даёт:**
- автоматически подтягивает сделки из amoCRM (ничего не надо выгружать вручную);
- показывает воронку и конверсии в трёх разрезах: **по источникам, по месяцам,
  по менеджерам**;
- считает юнит-экономику: **CAC, LTV, LTV:CAC, ROAS, средний чек**;
- позволяет вводить затраты (реклама + ЗП/налоги) и сразу видеть их влияние;
- выгружает всё в Excel;
- по кнопке даёт **рекомендации от нейросети** по данным страницы.

Источник правды — собственная база, а не таблица. Данные пересчитываются на лету.

## 3. Роли и кто что может

| Роль | Что доступно |
|------|--------------|
| **Администратор** | Всё: дашборды, ввод затрат, запуск синхронизации, управление пользователями |
| **Маркетолог** | Просмотр всех дашбордов, ввод «Затраты и касания», кнопка «Обновить сейчас», экспорт |

Пользователей создаёт администратор в разделе **«Пользователи»** (создание,
смена роли и пароля, отключение/удаление). Регистрация закрыта.

## 4. Как пользоваться — по вкладкам

Сверху на каждом дашборде — **панель фильтров**: период (с/по), менеджер,
источник, тип клиента. Фильтры применяются ко всей вкладке. При открытии по
умолчанию показывается **текущий месяц** (на «По месяцам» — текущий год).

### Обзор / По источникам
- Таблица метрик по каждому источнику + строка **«Все источники»**.
- **Воронка** (диаграмма): этапы MQL → SQL → встречи → счета → продажи. С этапа
  SQL бары разбиты по типу клиента (МКК/КК/СКК) — видно, какой сегмент тянет.
- Колонки: количество по этапам, конверсии, % неквала, затраты, CPL, цена
  встречи/продажи, выручка, ROAS, средний чек.
- Источники без результатов скрыты, чтобы не засорять вид.

### По месяцам
- Таблица: **месяцы по горизонтали, метрики по вертикали** — удобно сравнивать
  месяц к месяцу.
- Рост/падение конверсий подсвечено: **зелёная ▲** — выросло, **красная ▼** —
  упало (к соседнему месяцу).
- **Карточки по типам клиента** (МКК/КК/СКК): количество, конверсия, длина
  сделки + изменение к прошлому периоду.
- **Диаграммы**: конверсии по месяцам и отдельная — конверсия по каждому типу
  клиента (своя линия).
- Юнит-экономика: CAC, средний чек, LTV, LTV:CAC, ROAS, длина сделки.
- Можно сравнить **один месяц по годам** (например, все январи) — выбор в фильтрах.

### По менеджерам
- **Карточки по каждому менеджеру**: по типам клиента — конверсия MQL→успех и
  средняя длина сделки. Видно, кто с каким сегментом работает лучше.
- Сводная таблица по менеджерам.
- *Важно:* цена привлечения (CPL, ROAS) по менеджерам **не считается** — затраты
  привязаны к источнику, а не к человеку (это методическое ограничение).

### Затраты и касания
- Ввод (маркетолог/админ): **реклама по источникам** (месяц × источник × сумма ×
  касания) и **затраты по месяцам** (расходы на маркетинг и на продажи).
- После ввода оживают CAC, ROAS, цена встречи/продажи.

### Сделки
- Плоская таблица всех сделок с **поиском** (по ID / источнику / типу клиента) —
  для проверки данных.

### Экспорт
- Кнопка **«⬇ Excel»** есть на каждом дашборде (выгружает текущий вид с учётом
  фильтров) и на отдельной вкладке. Листы: по источникам, по месяцам, по
  менеджерам, сделки, реклама, затраты.

## 5. Как обновляются данные

Раздел **«Синхронизация»** (админ/маркетолог):
- **«Обновить сейчас»** — подтянуть свежие данные из amoCRM.
- **«Первичный бэкофилл»** (админ) — полная перезагрузка истории (обычно только
  при первом запуске).
- Автоматически данные обновляются **раз в сутки** без участия человека.
- Внизу — журнал запусков со статусом и количеством сделок/событий.

Сделки, которые **удалили или перенесли** в другую воронку в amoCRM, при
синхронизации автоматически убираются из отчётов (чтобы не искажали цифры).

## 6. Методика расчётов (простыми словами)

**Когортная логика — главное, что нужно понимать.** Все метрики привязаны к
месяцу, когда лид **создан**. Если лид пришёл в январе, а купил в июне — продажа
засчитывается в **январь** (не в июнь). Так конверсия месяца «дозревает» со
временем, и показатели одного месяца сопоставимы между собой (MQL/SQL июня не
смешиваются с выручкой январских сделок).

**Этапы воронки:** Лиды (MQL) → Возможности (SQL, заполнен «тип клиента») →
Назначено встреч → Проведено встреч → Выставлено счетов → Продажи. «Дубли» в
воронку не считаются.

**Юнит-экономика** (сверено с исходной таблицей — цифры сходятся):
- **CAC** (стоимость привлечения клиента) = (расходы на маркетинг + расходы на
  продажи) ÷ число продаж месяца.
- **Средний чек** = средний ежемесячный платёж клиента за платформу.
- **LTV** (прогноз выручки с клиента) = средний чек × 21 месяц.
- **LTV:CAC** — окупаемость привлечения (чем выше, тем лучше).
- **ROAS** = выручка ÷ рекламные затраты.

## 7. Рекомендации от нейросети

На дашбордах «По источникам / месяцам / менеджерам» есть кнопка
**«🤖 Рекомендации от нейросети»**. По нажатию (не автоматически) искусственный
интеллект анализирует показатели страницы и выдаёт: **закономерности, аномалии,
список рекомендаций**. Учитывает текущие фильтры. Удобно для быстрых выводов
перед планёркой.

## 9. На что обратить внимание (открытые вопросы)

- **Названия источников.** В рекламе («Затраты и касания») и в сделках amoCRM
  источники могут называться по-разному — тогда CPL/ROAS по конкретному источнику
  не сойдётся (общие месячные показатели корректны). При необходимости
  разработчик настроит сопоставление названий.
- **Поле «ежемесячный платёж»** в amoCRM должно быть заполнено — от него зависят
  средний чек и LTV.
- **Корректность CAC** зависит от своевременного ввода затрат по месяцам.
- Сейчас одна воронка и одна валюта (₽) — при необходимости расширяется.
